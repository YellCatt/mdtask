# MDTask

一个**基于 Markdown 表格**的轻量级任务管理工具，带守护进程常驻 + 定时邮件报告。

任务数据存在 `.md` 文件里，用 Markdown 表格维护——你可以用任何编辑器打开它手工改，也可以用 `mdtask` 命令行操作。守护进程后台常驻，定时生成日报/周报/月报/年报并通过邮件发出。

## 特性

- 📄 **纯 Markdown 存储**：所有任务是 `.md` 文件里的表格，人类可读、可直接用 git 跟踪
- 🖥️ **CLI 命令行**：`add / list / show / edit / done / doing / hold / cancel / rm / archive`
- 🤖 **守护进程常驻**：自动扫描 md 文件变化，为新任务补填「添加日期」
- 📧 **四周期邮件报告**：日报、周报、月报、年报，按配置时间点自动发送
- 🗂️ **自动归档**：完成的任务可自动或手动移入归档表
- 🔒 **原子写入 + 自动备份**：每次写入前备份旧版本到 `.mdtask-backup/`
- 📝 **多任务文件**：一个目录下放多个 `.md`，都会被合并读取
- 🌍 **时区固定东八区**：不受运行环境影响，适合服务器部署

## 快速开始

### 构建

```bash
go build -o mdtask ./cmd/mdtask
```

### 初始化

第一次运行时在当前目录自动生成 `config.yaml` 和 `tasks.md`：

```bash
./mdtask -f ./tasks
```

### 任务管理（CLI 模式）

```bash
# 列出所有任务
./mdtask list

# 添加
./mdtask add 完成项目提案 -p P1 -d 2026-09-15 -n "客户要求周五前交"

# 按状态筛选
./mdtask list -s done

# 按关键词搜索
./mdtask list -q 客户

# 标记状态
./mdtask done 3            # 把 ID 为 3 的任务标记为完成
./mdtask mark 5 doing      # 等价于 doing 命令
./mdtask cancel 8 9        # 支持一次操作多个 ID

# 编辑
./mdtask edit 3 -t "更新后的标题" -p P0 -d 2026-09-20

# 查看详情
./mdtask show 3

# 归档
./mdtask archive --days 7  # 把截止日期在 7 天前的已完成任务归档
./mdtask archive --all     # 连停滞(❌)一起归档

# 查看任务文件路径
./mdtask path
```

### 守护进程模式

```bash
# 后台常驻，自动生成报告 + 发邮件
./mdtask -f ./tasks -c ./config.yaml
```

守护进程启动后会：
1. 加载配置和所有 md 文件
2. 在启动目录下生成 `reports/` 子目录，写入一份完整的四周期报告
3. 启动邮件调度 goroutine，按 `config.yaml` 里的 `report.times` 发送邮件
4. 主循环每 10 秒扫描一次 md 文件，为新任务补填「添加日期」字段

进程会一直驻留直到被 `Ctrl+C` 或 `kill`。

## 任务文件格式

默认文件名 `tasks.md`（可在配置里改）。文件中包含两个 Markdown 表格：

### 主表（进行中任务）

```markdown
## 任务

| ID | 标题             | 状态 | 优先级 | 截止日期   | 备注               | 添加日期   |
|----|------------------|------|--------|------------|--------------------|------------|
| 1  | 完成项目提案     | ⏸️   | P1     | 2026-09-15 | 客户要求周五前交   | 2026-09-10 |
| 2  | 整理会议纪要     | ✅   | P2     | 2026-09-08 | 已发邮件           | 2026-09-09 |
```

### 归档表（已完成/已取消）

```markdown
## 归档

| ID | 标题        | 状态 | 优先级 | 截止日期   | 备注       | 添加日期   | 完成时间   |
|----|-------------|------|--------|------------|------------|------------|------------|
| 3  | 旧任务      | ✅   | P3     | 2026-08-01 |            | 2026-07-20 | 2026-08-02 |
```

### 表格规则

- 列名支持中英文别名，比如 `ID/编号/序号`、`标题/Title/名称`、`状态/Status/进度` 等
- 表头行可以随意增减，未知列会被原样保留
- **不需要手工写归档章节**：命令执行 archive 时会自动创建
- 多 md 文件：目录下所有 `.md` 会被合并读取，ID 全局唯一

### 四种状态

| Emoji | 命令名   | 含义       | 是否关闭 |
|-------|----------|------------|----------|
| ✅     | `done`   | 完成       | 是        |
| ⏸️     | `doing`  | 进行中     | 否        |
| ❌     | `hold`   | 停滞       | 否        |
| 🔴     | `cancel` | 取消       | 是        |

### 优先级

`P0`（最高）→ `P4`（最低）

## 配置

配置文件名为 `config.yaml`，与 mdtask 二进制放在同一目录，或运行时用 `-c` 指定。没找到时会自动生成一份默认配置。

所有字段：

```yaml
# 任务 md 文件目录
dir: tasks

# 每次写入前备份旧文件到 .mdtask-backup/
backup: true

# 颜色: auto（跟随终端）/ always / never
color: auto

archive:
  # 归档章节的标题（程序按这个标题找归档表）
  heading: 归档
  # 自动归档: -1 关闭 / 0 一标记结束就归档 / N 截止日期 N 天后才归档
  auto: -1
  # archive 命令是否连「停滞」一起搬走
  include_stuck: false

report:
  # 每天发送邮件报告的时间点（24 小时制）
  times:
    - "21:00"
    - "05:00"
  # 扫描 md 变化的间隔（秒）
  interval: 60
  # 生成报告后用默认程序打开
  open: false
  # 弹系统通知（Windows 气泡 / Linux notify-send / macOS）
  notify: true
  # 报告存放目录（相对 md 文件所在目录）
  dir: .mdtask-daily
  # 周报：周几出（1=周一 … 7=周日），0 关闭
  weekly: 1
  # 月报：每月几号出，0 关闭
  monthly: 1
  # 年报：哪天出，格式 MM-DD，留空关闭
  yearly: "01-01"

mail:
  # SMTP 服务器
  smtp_host: smtp.qq.com
  # 端口：465 直连 TLS（推荐），587 支持 STARTTLS
  smtp_port: 465
  # 发件邮箱
  from_email: "you@example.com"
  # 邮箱授权码（不是登录密码，QQ/163 都在设置里单独生成）
  auth_code: "your-auth-code"
  # 收件人，多个用逗号分隔
  to_email: "you@example.com"
  # 服务器用的是自签证书时才开
  tls_skip_verify: true
  # 连接超时（秒）
  timeout: 15
```

## 命令行参数

守护进程模式下支持：

```
mdtask [-f <dir>] [-c <config>] [--no-backup]

  -f, -file, --file       任务文件目录（默认读 config.yaml 里的 dir）
  -c, -config, --config   配置文件路径（默认自动查找 config.yaml / config.yml）
  --no-backup             禁用备份（会覆盖配置里的 backup）
```

优先级：命令行参数 > 环境变量 `MDTASK_FILE` > 配置文件 `dir`

## 报告

### 磁盘报告

守护进程启动时立即生成一份完整的四周期报告，写入**程序运行根目录**下的 `reports/` 子目录（与 `logs/` 同级）：

```
reports/
├── daily/
│   ├── 2026-09-09.txt        # 日报总结「昨天」
├── week/
│   ├── 2026-09-07_2026-09-13.txt
├── month/
│   ├── 2026-08.txt           # 月报总结「上个月」
└── year/
    ├── 2025.txt              # 年报总结「去年」
```

日报/月报/年报用「上一周期」的原因：报告总结的是**已完成的任务**，当前周期还没走完。

### 邮件报告

按 `config.yaml` 里的 `report.times` 触发（例：每天 21:00 和 05:00）。
四种周期同时检查，该发的会一起发出。

防重发机制：进程维护一个内存中的 `sentTracker`，记录每个周期上一次成功发送的 key。
进程 crash 重启后，`initSentTracker` 会根据当前时间正确恢复状态，不会漏发或重发。

## 备份机制

- 每次写入前把当前文件复制到 `.mdtask-backup/` 目录
- 文件名格式：`20260910-210005.123.md`
- 最多保留最近 **10** 份，超出自动清理最旧的

备份目录在任务 md 文件所在目录下：

```
tasks/
├── tasks.md
└── .mdtask-backup/
    ├── 20260910-210005.123.md
    ├── 20260910-203012.456.md
    └── ...
```

## 日志

守护进程运行时会在**程序运行根目录**（启动 mdtask 时的工作目录）下创建 `logs/` 子目录，按天轮转：

```
logs/
├── 2026-09-10.log
├── 2026-09-09.log
└── ...
```

- 最多保留 **7** 天
- 同时输出到 `stderr`（Error 及以上）和文件（所有级别）
- 格式：`[2026-09-10 21:00:05] INFO runMailer 计算下次发送时间 next=...`

## 常见问题

### 为什么时区固定在东八区？

守护进程里所有时间计算（报告触发点、日期分割、周期 key）都绑定本地日界线。
硬编码为东八区，保证无论进程跑在哪台机器上，行为都一致。

### 手工编辑 md 文件后会怎样？

守护进程每 10 秒重新 `Load()` 一次所有 md 文件，手工编辑会在下一轮扫描中被感知。
如果是新任务（有 ID 但没有「添加日期」），会自动补填今天的日期。

### 多任务文件怎么合并？

目录下所有 `.md` 都会被读入，按文件名字母序排。ID 必须全局唯一；如果冲突不会报错，但命令行会优先匹配第一个找到的。

### 进程 crash 重启会重复发邮件吗？

不会。`initSentTracker` 在启动时根据当前时间恢复 sentTracker 的状态，
让它「看起来已经在上一个触发点运行过」，避免启动时重发上一周期的报告。
